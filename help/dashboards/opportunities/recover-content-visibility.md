# コンテンツの可視性を回復

AI エージェントは、アクセスできるコンテンツのみを引用できます。 ページ上の重要なコンテンツ（製品説明、ユーザー評価、レシピ、コメントなど）がクライアントサイドレンダリングや動的な読み込みの背後に隠れている場合、AI エージェントは完全に見逃してしまい、引用する可能性のあるシステムに対して貴重なコンテンツが見えなくなります。

コンテンツの可視性を回復のオポチュニティは、サイト内で可視性のギャップが存在するページを特定します。 影響を受ける各ページについて、AI エージェントビューから欠落しているコンテンツを正確に表示し、そのギャップをハイライト表示すると、CMS の変更や開発者の関与なしに修正を適用できます。

ここでは、次の 3 つの主要指標を一目で確認できます。

- **URL 数** - コンテンツの可視性にギャップがあると特定されたページの数。
- **推定コンテンツゲイン** - 最適化を適用することで回復できるコンテンツの推定乗数。
- **コンテンツの可視性 (平均)** - 影響を受けるページをまたいで、AI エージェントに現在表示されているコンテンツの平均割合。

![コンテンツの可視性を回復ダッシュボード](/help/dashboards/opportunities/assets/recover-content-visibility-overview.png)

このオポチュニティの概要をビデオで視聴する場合は、[コンテンツの可視性を回復](https://www.youtube.com/watch?v=BigPyJssFCw)をご覧ください。

このオポチュニティは、[Edge での最適化](/help/dashboards/optimize-at-edge/overview.md)を使用することで最適化できます。 最適化は、人間の訪問者に影響を与えることなく、AI エージェントにのみ配信されます（ボットのみの配信）。 その後、最適化は、CDN レイヤーで適用され、CMS の変更は不要で、開発者のエンゲージメントなしに数分で有効になるので、迅速で低リスクなデプロイメントが可能です。

## 仕組み

LLM Optimizer は、AI エージェントがアクセスできる内容と、実際にページ上に存在する内容を比較して、ページを分析します。 エージェントトラフィックは多いが、コンテンツの可視性が低いページは、エージェントトラフィック量に基づいて優先順位が付けられ、**候補を含む URL** テーブルに表示されます。

影響を受ける各 URL について、LLM Optimizer は以下を提供します。

- **AI 分析** - 欠落しているコンテンツおよびそのコンテンツが LLM の引用可能性に対して重要な理由の説明と、回復可能なコンテンツ参照のリスト
- **コンテンツの可視性** - そのページで AI エージェントに現在表示されているコンテンツの割合
- **コンテンツゲイン率** - 最適化を適用した場合に回復できるコンテンツの推定乗数
- **プレビュー** - 最適化前後のページの外観を並べて表示する HTML 比較。これにより、デプロイ前に変更を検証できます。

この修正は、アドビの Edge ベースのデプロイメント機能である [Edge での最適化](/help/dashboards/optimize-at-edge/overview.md)を使用して適用されます。この機能は、完全にプリレンダリングされた AI 対応の HTML スナップショットを CDN レイヤーの LLM ユーザーエージェントに提供し、CMS にアクセスすることなく、以前に非表示になっていたコンテンツを回復します。

## URL と提案

**候補を含む URL** テーブルには、影響を受けるすべてのページがリストされ、分類別にフィルタリングできます。 各 URL について、次の操作を実行できます。

- **行を展開**：欠落しているコンテンツおよびそのコンテンツが重要な理由を含む AI 分析を表示します。
- **プレビュー**：現在のページと最適化後のバージョンの HTML を並べて比較します。
- **修正済みとしてマーク**：問題が解決したら実行します。
- **無視**：関連しない候補に対して実行します。

候補は、**現在の候補**、**修正された候補**、**無視された候補**&#x200B;の 3 つのビューに整理されます。 候補がデプロイされると、その候補は修正された候補に移動し、ステータスが&#x200B;**最適化済み**&#x200B;になり、**ライブ表示**&#x200B;アクションでエージェントトラフィックに対する最適化がライブであるかどうかを確認できます。 また、修正された候補は、いつでもロールバックすることもできます。

![最適化済みステータスの修正された候補](/help/dashboards/opportunities/assets/recover-content-visibility-fixed.png)

## 最適化のデプロイ

候補を確認し、最適化する URL を選択したら、「**最適化をデプロイ**」をクリックして、CDN Edge で修正を公開します。 **Edge にデプロイ**&#x200B;確認ダイアログには、選択された URL、そのタイプ（プリレンダリング）および適用される候補が表示されます。 デプロイメント後、正常に最適化された URL を確認する確認画面が表示されます。

>[!NOTE]
>
>最適化をデプロイするには、Edge での最適化のオンボーディングプロセスを完了する必要があります。 まだオンボードしていない場合は、「**最適化をデプロイ**」をクリックすると、オンボーディングプロセスに移動します。 Edge での最適化の仕組み、サポートされている CDNプロバイダー、オンボーディングプロセスについて詳しくは、[Edge での最適化](/help/dashboards/optimize-at-edge/overview.md)ページを参照してください。

![Edge にデプロイダイアログ](/help/dashboards/opportunities/assets/recover-content-visibility-deploy.png)

## よくある質問

**AI エージェントからページコンテンツが非表示になっているのはなぜですか？**

ほとんどの最新の web サイトは、最初のページリクエスト後にコンテンツを動的に読み込むために JavaScript に依存しています。 AI エージェントは通常 JavaScript を実行しないので、クライアントサイドでレンダリングされるコンテンツ（製品リスト、ユーザーレビュー、ブログ記事へのリンクなどの要素）は、人間の訪問者には完全に表示されていても、AI エージェントには決して認識されません。

**この最適化は、人間の訪問者または SEO ボットに影響を与えますか？**

いいえ。 Edge での最適化は、AI ユーザーエージェントのみをターゲットにしています。 人間の訪問者や SEO ボットは、以前とまったく同じように元のページを受け取り、エクスペリエンスやパフォーマンスに変更はありません。

**CMS を変更したり、開発者を関与させたりする必要がありますか？**

いいえ。 最適化は CDN Edge で適用され、オーサリングの変更、コードのデプロイメント、開発者のエンゲージメントは一切必要ありません。 Edge での最適化にオンボードすると、LLM Optimizer インターフェイスから直接、数分で変更のデプロイとロールバックを行うことができます。

**デプロイ後にページコンテンツが変更された場合はどうなりますか？**

コンテンツの可視性を回復では、LLM Optimizer はキャッシュの TTL 設定を低く指定し、サイト上のコンテンツが更新されると数分以内に更新がトリガーされます。 AI エージェントは、常に最新バージョンのコンテンツを受け取ります。

**Edge での最適化を開始するにはどうすればよいですか？**

完全なオンボーディングプロセス、CDN 設定ガイド、前提条件について詳しくは、[Edge での最適化](/help/dashboards/optimize-at-edge/overview.md)ページを参照してください。
