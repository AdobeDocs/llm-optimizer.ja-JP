# 製品詳細ページのエンリッチメント

AI エージェントは、自分で完全に理解できる商品しかレコメンデーションできません。 多くのコマースのストアフロントでは、商品ページは人間向けに設計されています。 そのため、これらの製品は、JavaScript でレンダリングされたタブ、拡張可能なパネル、ショッピングウィザード、インタラクティブモーダル、製品のバリエーション、仕様、機能を表示するリンクなどに依存しています。 AI エージェントは商品詳細ページの詳細を解析しないため、人間の訪問者が完全に確認できる場合でも、AI による検出を実現している LLMweb クローラーでは、この豊富な商品データを見ることはできません。

「製品詳細ページの強化」オポチュニティでは、この可視性のギャップが存在する Adobe Commerce カタログ内の製品ページを特定します。 Adobe Commerce Catalog を利用すると、ストアフロントで AI 担当者がアクセスできる商品と、カタログで利用可能な全商品データを比較し、AI 担当者のビューに表示されない、あらゆる属性、バリエーション、商品特性の詳細を明らかにできます。

ここでは、次の 3 つの主要指標を一目で確認できます。

- **製品ページ** — カタログデータの可視性ギャップで識別されたすべての製品詳細ページのリスト。
- **エージェントトラフィック** — ユーザーの代理で動作する自律型 AI エージェント（LLM を活用したアシスタントやボットなど）によって開始および実行され、コンテンツを検索、取得、またはエンゲージするサイトの合計訪問数とインタラクション数。

![製品詳細ページダッシュボードの強化](/help/dashboards/opportunities/assets/enrich-product-detail-pages-overview.png)

このオポチュニティは、[Edge での最適化](https://experienceleague.adobe.com/ja/docs/llm-optimizer/using/resources/optimize-at-edge/overview#what-is-optimize-at-edge)を使用することで最適化できます。最適化は AI エージェントのみに配信され、人間の訪問者には影響しません（ボット専用配信）。CMS やカタログを変更することなく CDN レイヤーで適用でき、開発者が関与することなく数分で有効になります。そのため、大規模な商品カタログに対しても、迅速かつ低リスクなデプロイメントが可能となります。

## 仕組み

Adobe Commerce Catalog Agent は、バリエーション、より詳細な商品関係、属性、ファセット、カテゴリーメタデータ、あらゆる商品特性など、商品カタログデータ全体を読み取ります。 次に、対応するストアフロント PDP の AI エージェントが実際にアクセスできるものとデータを比較します。 AI クローラーからカタログデータが非表示になっているページは、エージェントトラフィック量で優先順位付けされた **URLと提案**&#x200B;テーブルに表示されます。

影響を受ける各製品ページについて、LLM Optimizer は以下を提供します。

- **AI 分析プレビュー** – 製品のバリエーション、サイズオプション、材料仕様、互換性の詳細などの回復可能なデータ ポイントのリストを含む、AI エージェントビューに表示されないカタログ情報の完全なリストと、それが LLM 主導の製品検索に必要な理由。

この修正は、アドビの Edge ベースのデプロイメント機能である [Optimizer at Edge](https://experienceleague.adobe.com/ja/docs/llm-optimizer/using/resources/optimize-at-edge/overview#what-is-optimize-at-edge) を使用して適用されます。この機能は、完全にプリレンダリングされた AI 対応の HTML スナップショットを、CDN レイヤーの LLM ユーザーエージェントに提供します。これにより、Commerce のカタログや人間向けのストアフロントの UI に手を加えることなく、これまで非表示にされていたカタログデータ（製品バリエーション、技術仕様、機能の詳細など）をすべて復元できます。

![URL と提案](/help/dashboards/opportunities/assets/enrich-product-detail-pages-suggestions.png)テーブル

## URL と提案

**URL と提案**&#x200B;テーブルには、最適化からメリットを得るすべての識別された製品ページが一覧表示されます。 各製品 URL について、次の操作を実行できます。

- **プレビュー**&#x200B;をクリックすると、AI 分析が表示され、不足しているカタログ情報と、それが AI による情報発見にとって重要な理由を確認できます
- 最適化のデプロイと検証が完了したら、**修正済みとしてマーク**&#x200B;します
- マーチャンダイジング戦略に適さない提案を&#x200B;**無視**&#x200B;します。

提案は、**現在の提案**、**修正された提案**、**無視された提案**&#x200B;の 3 つのビューに整理されます。候補がデプロイされると、その候補は修正された提案に移動し、ステータスが&#x200B;**最適化済み**&#x200B;になり、**ライブ表示**&#x200B;アクションでエンリッチメントがエージェントトラフィック向けに反映されていることを確認できます。修正された提案は、いつでもロールバックすることができます。

## 最適化のデプロイ

候補を確認し、最適化する製品ページを選択したら、「**最適化をデプロイ**」をクリックして、CDN Edge でエンリッチメントを公開します。 **Edge にデプロイ**&#x200B;確認ダイアログには、選択された製品 URL、最適化タイプおよび適用されるエンリッチメントが表示されます。 デプロイメント後、正常に最適化された製品ページを確認する確認画面が表示されます。

最適化は、CDN エッジレイヤーを介してAI ユーザーエージェントにのみ配信されます。 訪問者は、PDP のデザイン、ページのパフォーマンス、ブランド体験に変更を加えることなく、既存のストアフロント体験を以前とまったく同じように確認し続けることができます。

>[!NOTE]
>
>最適化をデプロイするには、（1）LLM Optimizer を Adobe Commerce に接続し、（2）Optimize at Edge のオンボーディングプロセスを完了する必要があります。

Commerce インスタンスがまだ LLM Optimizer に接続されていない場合は、エンリッチメントを適用する前に接続設定に移動します。

まだオンボードしていない場合は、「**最適化をデプロイ**」をクリックすると、オンボーディングプロセスに移動します。 Edge での最適化の仕組み、サポートされている CDNプロバイダー、オンボーディングプロセスについて詳しくは、[Edge での最適化](https://experienceleague.adobe.com/ja/docs/llm-optimizer/using/resources/optimize-at-edge/overview#what-is-optimize-at-edge)ページを参照してください。

## よくある質問

**製品カタログデータが AI エージェントに表示されないのはなぜですか？**

Commerce ストアフロントは、人間の買い物客向けに構築されています。製品の特性、バリエーション、サイズ オプション、素材の詳細、その他の技術仕様は、多くの場合、タブ、折りたたみパネル、ポップアップモーダル、リンク、ショッピングウィザードなどの JavaScript によるインタラクションを通じて表示されます。AI エージェントは製品詳細ページの奥深くまで解析しないため、製品カタログにすべてのデータが含まれていても、LLM クローラーからは見えません。その結果、AI エージェントは、実際に利用可能な製品情報のごく一部だけを基に製品を推奨することになります。

**この最適化によって、どのような種類の製品データを復元できますか？**

カタログエージェントは、AI エージェントが現在ストアフロントからアクセスできない、Adobe Commerce カタログ内のすべての製品情報を復元します。これには、製品の特性、関連情報、バリエーション（サイズ、色、構成）、技術仕様と属性、互換性の詳細、カテゴリ メタデータ、ファセット値が含まれます。

**この最適化は、人間の訪問者、SEO ボット、またはストアフロントのパフォーマンスに影響しますか？**

いいえ。 Edge での最適化は、AI ユーザーエージェントのみをターゲットにしています。 人間の訪問者と SEO ボットには、これまでどおり元の製品ページが提供されるため、ユーザーエクスペリエンス、ページの読み込みパフォーマンス、ストアフロントのデザインに変更はありません。

**Commerce カタログや CMS を変更したり、開発者に依頼したりする必要はありますか？**

いいえ。 この最適化は CDN のエッジレイヤーで適用されるため、Adobe Commerce カタログの変更やコードのデプロイ、開発者による対応は必要ありません。Edge での最適化にオンボードすると、LLM Optimizer インターフェイスから直接、数分でエンリッチメントのデプロイとロールバックを行うことができます。

**デプロイ後に製品コンテンツが変更された場合はどうなりますか？**

製品詳細ページのエンリッチメントのオポチュニティでは、LLM Optimizer は低いキャッシュ TTL を使用するため、Commerce カタログ内の製品情報が更新されると、数分以内に更新内容が反映されます。AI エージェントは、常に最新の製品データを受け取ります。
